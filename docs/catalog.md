# 元数据目录教程

目录把作品身份、具体内容与发行记录分开保存。这样可以复用同一份录音或正文，同时保留每次发行的编号、包装和实际目录。

## 八类条目

| 条目 | 回答的问题 | 例子 |
| --- | --- | --- |
| 主体 Agent | 谁参与了创作？ | 作者、乐团、出版社、虚构角色 |
| 集合 Collection | 哪些作品属于同一企划或系列？ | 跨媒体企划、作品系列 |
| 作品 Work | 这是什么独立创作？ | 歌曲、专辑、小说、游戏 |
| 内容单元 ContentUnit | 作品内部如何分章或分集？ | 第三章、第 78 集、游戏路线 |
| 表达 Expression | 具体是哪一份内容？ | 原唱录音、翻唱、译本、导演剪辑 |
| 发行 Release | 哪一次公开出版或发布？ | 普通版、限定版、地区版、免费数字版 |
| 载体 Medium | 这一发行由哪些承载单元组成？ | CD、BD、纸质册、数字集 |
| 收录位置 Track | 内容在载体的什么位置？ | 第 1 轨、A1、页码范围或菜单项 |

这些是固定种类。描述性分类用标签，可填写的附加字段来自站点定义。简单作品只建立有来源的条目，不必凑齐八类。

## 歌曲与专辑：复用同一录音

歌曲 A 是一个 Work，原唱录音 A1 是它的 Expression。单曲、专辑和精选集各建自己的 Release；如果收录的是同一份录音，它们都引用 A1。

```text
歌曲 A（Work）
  └ 原唱录音 A1（Expression）
      ↑ 收录                         ↑ 收录
单曲发行 → CD → 第 1 轨       专辑发行 → CD → 第 3 轨
 Release  Medium  Track        Release  Medium  Track
```

新录音或有实质内容差异的版本另建 Expression。仅格式、载体或编码不同，不足以证明是新的录音。

商品页的曲目表支持本版收录，不单独证明独立母版、SKU 专属录音或与另一发行共用录音；品番和商品名不作为录音的版本名。无法确认内容身份时，先补有据的发行对象并保留待核缺口。

每个发行的 `subjects` 声明实际收录表达所属的全部 Work。专辑作为独立作品时，可用有序关系记录概念编排；实际版次的曲序仍以载体和收录位置为准。

`subjects.role` 使用当前启用的 `release_role` 词项：例如专辑主作品用 `primary`，收录的歌曲作品用 `track_work`，有据的特典作品才用 `supplement`。缺少准确词项时提出定义缺口，不用特典角色代替普通曲目；role 也不替代 `Track.contents`。

## 图书与分集：目录和具体内容分开

一本小说是 Work，“第三章”是 ContentUnit。原文和译文各建 Expression，并关联这一章；它们之间的派生关系说明“翻译自”。

整本译文可以通过表达组合关系有序包含各章译文。精装、文库和电子版分别建 Release，按实际目录和页码收录这些表达。

动画采用同样方式：稳定分集是 ContentUnit，具体正片或剪辑是 Expression。正式题名里的季数或卷号若用于区分独立作品，按来源保留；同作品内部的部分才使用内容单元。

## 盒装与附赠：按实物记录

盒装先建立一次真实发行，再按实物建立分盘和收录。每个 Track 引用实际内容的 Expression，发行声明对应的全部 Work。

盒装品番属于盒装发行，不能挂到其中某部作品的单品发行上。只有来源证明汇编本身有独立创作身份时，才另建汇编 Work；用于归拢版本或企划时可以使用 Collection。

盒内附件、店铺赠品与真实盘片分别记录，不为没有来源的包装内容虚构载体。

例如，两个作品的盒装可以这样记录：

```text
Release：作品 A + 作品 B 盒装
  subjects：Work A、Work B
  Medium 1
    Track 1 → contents → Expression A1 → Work A
  Medium 2
    Track 1 → contents → Expression B1 → Work B
```

## 组成、版本组和署名

- **表达组成**：整体与部分 Expression 属于同一 Work，通过定义中用途为 `expression_composition` 的关系连接；常见种子码为 `expression_part`。
- **显式版本组**：Release 通过用途为 `release_group` 的关系归到一个 Work 或 Collection；常见种子码为 `edition_of`。共同收录某首歌不等于属于同一版本组。
- **创作与参与关系**：从适用的作品、篇目、表达或发行连接到主体。关系方向、允许层级和上下文字段均按当前定义选择。

同一演员在同一作品里担任不同角色时，用多条具有不同角色上下文的关系表达，不重复建演员。

详情页的关系目录按定义分组，并区分作品、表达和发行等层级，可搜索名称、别名及关系属性。同一对象的多条署名合并展示，仍保留每条署名的职位、语言、适用上下文等属性；同名但身份不同的对象分别保留。主体间的直接关系可展示头像或立绘，成员职责和有效日期只显示实际录入的关系属性。

## 标签、货架与多语言

实体种类决定结构，标签描述主题与风格，货架组织浏览入口，语言资料保存不同名称。

### 标签

标签是平铺的自由字符串，例如「科幻」「机甲」「J-Pop」，保存在 `attributes.tags` 中。它们不改变实体种类、归属或可写字段；承载格式、发行地区和版别仍放在对应层级。探索页支持两种标签匹配方式：「全部包含」只显示同时包含所有已选标签的条目，增加标签会缩小范围；「任一包含」显示包含至少一个已选标签的条目，增加标签会扩大范围，默认使用此模式。列表 API 的 `tags_mode=all` / `any` 对应这两种方式，省略时为 `any`，普通列表和关键词搜索均适用；其它筛选条件仍与标签条件取交集。建议词来自 active 词条的频次聚合。

### 货架与首页分区

系统货架由管理者配置查询规则，按标签、字段、词项或关系组织作品。规则条件之间取交集，同一条件里的候选取并集；货架不会把载体格式变成作品属性。

登录用户可以调整首页顺序与显隐。接口还支持覆盖自己的系统货架展示规则或自建分区，最多 20 项；可用设置入口以页面为准，个人设置不影响他人。维护协议见[动态定义与配置](/api-definitions#货架与外部权威库)。

### 多语言名称

语言资料按语言分组，每项可包含题名、简短简介、条目正文和别名；原语言题名放在对应项中。界面支持简体中文、繁体中文、英语和日语，并按可用语言回退；回退只影响显示，不修改原始资料。

字段、关系、词表和货架的显示名来自站点定义，启用的定义名称要求四语齐备；实体自身发布时至少有一条语言资料。名称填写和图片顺序见[词条编辑与审查规范](/editing-guide)。

## 填写与查看

### 正文与结构化资料

条目同时提供文章式说明与结构化记录。简介用几句话介绍对象；在编辑器的「条目正文」分区选择语言，默认用可视化编辑器撰写创作背景、内容介绍、发行沿革等说明，也可切换 Markdown 源码或预览。工具栏提供段落与标题、列表、链接、图片、表格、公式、脚注及撤销重做；光标进入表格后可增删行列，选择脚注后可编辑参考内容。每种语言的正文最多 100000 个字符，阅读页显示实际语言并提供已有正文的语言切换。

可视化与源码模式共用同一份 Markdown 正文，切换模式不自动保存条目。打开可视化模式时会核对转换是否保留全部内容；不支持的语法会保留原文并回到源码模式，不强制转换。正文中的公式使用 LaTeX，脚注仍保存为 Markdown 引用。

正文支持标题、自动目录、表格、图片、链接和脚注。条目链接使用 `[名称](/catalog/条目UUID)`；正文图片可引用存储服务的稳定地址。正文标题会生成 `#article-section-标题` 锚点，可直接分享文章目录中的链接。脚注写法为 `正文[^official]`，在文末用 `[^official]: [官方资料](https://example.org/source)` 定义引用。

日期、人员、品番、收录及关系仍填写在结构化字段中，供筛选、比较与 API 使用；正文中的描述不会自动生成或改写这些事实。正文由目录服务共同维护，讨论和署名考据在社区进行；它不等于被编目作品或 Expression 的原文。

正文与资料在同一个工作副本中编辑，可以多次保存并形成 commit；push 后免审账号直接合入，其他账号发起 PR，合并前公开条目保持旧内容与版本。来源与查证记录可省略，正文脚注按阅读需要使用。在「历史变更」查看正文和资料的变化、比较版本或将旧内容载入副本；恢复仍形成一次新提交。

### 资料编辑

所有条目的详情地址都是 `/catalog/<id>`。从详情进入编辑，先核对名称与归属，再填属性、图片、关系、修改说明和来源。

归属通常不能直接改变。发现层级或归属错误时，先查阅现有引用并请有权限的成员处理，避免产生新的重复条目。

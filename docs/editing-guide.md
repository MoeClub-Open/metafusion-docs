# 词条编辑与审查规范

编辑的目标是让资料准确、容易核对。可以先修正一个译名、补一条来源或完善一项参与关系，不必一次补齐发行链。元数据可以独立投稿；有权提供文件时再按[资源上传与下载](/upload-download)上传。

编辑无需先运行质检、完成核对清单或达到某个完整度。质量报告、评分和缺项提示仅供参考，缺封面、缺署名或目录尚未补齐不会阻止提交当前修改。

## 投稿与编辑步骤

1. **找到记录**：搜索名称或编号，已有身份可直接复用；同名不等于同一实体。
2. **在副本中编辑**：从详情页进入编辑，或在副本中新建条目。参考[元数据目录教程](/catalog)选择合适层级，填写当前能确认的资料。
3. **继续修改**：可以跨条目多次保存，也可邀请协作者。保存的是服务器副本，公开条目保持原内容。
4. **创建提交**：检查差异，用简短说明创建 commit；可以继续编辑并产生多个 commit。
5. **推送并核对**：免审账号可直接合入，其他账号发起 PR。按实际结果核对条目、关系、收录和历史；出现冲突时比较基线、当前值与自己的修改，解决后再推送。

来源与查证记录可补充，不要求填写，也不作为编辑、提交或合并的门槛。不要为了满足格式造来源；已有资料按原样保留。

## 名称与多语言

采用来源支持的正式名称，在相应语言中补充简介和有据可查的别名。中文译名须有权利方或授权本地化渠道的证据，并核对适用地区、作品和版次；没有官方中文译名时保留原名，原语言资料即可满足语言资料要求，不必补齐中文名称。不要自行翻译、音译，或将社区、聚合站、机器翻译提供的名称直接写成中文题名或别名。

非官方译名需要名称级的明确标记（如 `nonofficial`），且编辑、API 与展示均须支持该标记。当前名称字段尚无此能力，因此暂不录入非官方译名；不要伪造字段、添加虚构语言标签，或将「非官方」拼进名称。已有中文名称若缺证应先核实来源，不直接批量清空。

Work 使用作品本身的名称；Release 原样保留发行方为该版使用的名称，不强制删去名称中的版别或格式。网页标题和界面规格标签不自动等于正式名称，其他规格仍记录在对应字段。

个人与团体采用公开使用的名称，不同艺名可以记录为别名，通过参与关系连接作品，避免为每部作品重建人物。原语言应与对应语言资料一致；新增字段、货架或外部库定义时，启用名称须四语齐备。

## 图片与外部编号

使用清晰、完整、有权引用的图片，可补充出处，保持自然比例。图片按保存顺序展示，首张作为封面；外部地址失效时更新，临时下载地址不用于长期封面。官方图源不自动意味着允许转载，权利不明时留空。

编号保留官方格式，核对所属版次；图书 ISBN 等标识还应核对校验位。可用外部数据库以编辑界面为准，登记数据库不代表支持自动导入。

图片比例和 ISBN 校验位等属于编目审查要求，不都是服务端通用拦截项。

## 复杂条目的建模参考

下面说明复杂条目中常见的事实区别，不是提交前必须逐项完成的检查表。建模示例在[元数据目录教程](/catalog)，精确字段约束在[实体模型与字段](/frbr-model)。

| 项目 | 核对内容 |
| --- | --- |
| 内容与复用 | 同一份录音、正文或剪辑被多次发行时共用 Expression；有实质创作差异时才另建表达。商品页曲名与品番只证明本版收录，不证明 SKU 专属录音或独立母版；不得据此填录音版本名。整体与部分表达同属一个 Work，顺序来自表达组合关系 |
| 发行与盒装 | 盒装编号在盒装 Release，单品编号在各自发行；subjects 覆盖实际收录表达所属的全部 Work，正曲不标为特典作品。包装名称不足以证明独立汇编身份，显式版本组也不能由共同收录推断 |
| 实际目录 | 分盘、分卷、曲目符合实物或发布记录；定位注明时间、页码或路径的参照范围。盒内附件、渠道赠品与真实载体分开记录 |
| 关系 | 选择当前定义中启用的关系，核对方向、允许层级、基数、同域和无环规则；属性引用的实体也在允许范围内 |
| 署名上下文 | 精确职位优先用对应关系；只有通用参与关系适用时才保留职位原文，不重复建通用边。作词作曲通常归歌曲作品，本次录音的编曲、制作、录音和混音归对应表达，并保留版次上下文。共同署名逐人保留，不补造未注明的职位；同一演员的多个角色用角色、语言或适用篇目区分 |

保存多层条目时逐步核对，每一步成功不代表整条发行链完成。后续失败时说明已保存与尚未完成的部分，避免重复创建。

需要讨论完整性时，可将任务范围内的事实对应到字段或关系，并说明尚未确定的信息。艺人介绍提及动画歌曲，不足以证明整张专辑是原声带；初回封入、随机数量与渠道赠品条件也不能省略。自动质检的 `complete` 仅表示响应 `checks` 中的结构检查通过，不证明来源支持结论或已补齐所有署名。

来源引用与原始资料归档是不同记录。修订可保存操作及字段的来源指针，但提交 URL 和引用说明不会自动保存网页原文，提取摘要也不能代替完整原始资料。要求完整保留时，应说明已保存的事实、仍可复核的来源，以及尚未归档或无法映射的信息。

## 修改审核与历史

条目没有草稿或发布状态。正常条目为 `state=active`、`review_status=reviewed`。编辑副本和 commit 不改变正式条目；普通账号 push 发起 PR，具有 `catalog.review.bypass` 的账号可直接合入。PR 合并前当前条目保持旧内容与版本。

PR 可以继续追加提交、讨论、关闭或重新打开。合并保留每个 commit 的原作者，并另记合并者；个人主页按已合入提交展示贡献。修订历史可核对旧内容，恢复仍形成新修改；实体身份合并与退役由具有生命周期管理权限的成员处理。

## 疑似重复与合并

先比较来源、创作者、编号、所属层级和实际内容，确认同一实体后再提出合并。不同表达或发行版通常各自保留。

合并由具有生命周期管理权限的成员执行。目标需同种类、同归属且为 `active`；引用迁往保留实体，旧地址可跟随到它，双方修订历史保留。当前没有撤销合并入口，执行前确认方向与冲突。
